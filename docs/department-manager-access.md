# صلاحيات مديري الأقسام

من إعدادات الشركة → المسؤولون الفرعيون، افتح حسابًا أو أنشئ حسابًا، وألغِ «الوصول إلى كل أقسام الشركة»، ثم اختر قسمًا أو أكثر والصلاحيات المطلوبة.

- مدير القسم يرى الموظفين الموجودين حاليًا في أقسامه فقط، وسجلاتهم التي تقع داخل هذه الأقسام حسب التاريخ. لا تُعرض السجلات السابقة في قسم آخر، ولا سجلات موظف انتقل خارج نطاقه. مراجعة التاريخ الكامل لإدارة الشركة.
- يمكن منح تعديل مسودة الجدول، مراجعة الطلبات، التقارير والطباعة. إدارة الموظفين والأقسام والشيفتات والإعدادات والحسابات ليست ضمن صلاحيات الحساب المحدد بالأقسام.
- حفظ المسودة يدمج خلايا الأقسام المسموحة فقط؛ يحتفظ ببقية بيانات الشركة وبيانات الدخول والإجازات والنسخة المنشورة. تعارض النسخة يرجع 409، ولا يستبدل تعديلات جلسة أخرى.
- نشر الجدول العام واعتماد/إعادة فتح الشهر لإدارة الشركة. مدير القسم يرفع مسودته للمراجعة ثم تنشرها الإدارة.
- نطاق التقارير والاستثناءات والتصدير يُطبّق قبل تجميع الموظف/اليوم والعدّ والتقسيم إلى صفحات. طلب التبديل خارج النطاق لا يظهر ولا يمكن مراجعته.
- كلمات المرور وبيانات الاتصال وسجل النقل لا تصل إلى مدير القسم عبر البيانات الرئيسية. الملف الكامل وسجل تدقيق الموظف لإدارة الشركة؛ تفاصيل اليوم والطلبات متاحة من قوائمها.
- الصلاحيات تُخزن في system_data تحت مفاتيح منفصلة لكل حساب، وليس داخل بيانات الموظفين أو JWT. يُتحقق منها عند كل طلب؛ السحب أو الحذف يعمل على الجلسات القائمة دون انتظار انتهاء التوكن. لا يلزم تغيير جدول قاعدة البيانات.
- الحسابات القديمة تحتفظ بصلاحياتها الحالية الكاملة على السيرفر حتى تحفظ الإدارة إعداداتها صراحة. راجع هذه الحسابات بعد التحديث وحدد صلاحياتها وأقسامها. حساب الشركة الأساسي والمدير العام يحتفظان بالوصول الكامل.
- حساب الشركة العام المفوض تُطبّق صلاحياته على حقول الحفظ ونقاط API كذلك، ولا يمكنه منح صلاحيات لا يملكها. بيانات الدخول لا تُعرض لمن لا يملك إدارة الموظفين/الإعدادات.

الواجهة تستقبل الصلاحيات الحالية مع تحديث البيانات المعتاد. لا تُستخدم النسخة المحلية للمسؤول كبديل عن فشل قراءة السيرفر، لتجنب إعادة إظهار بيانات كانت متاحة قبل تغيير النطاق. لا تضيف هذه الميزة أي مزامنة أو كتابة دورية.

التحقق: اختبارات وحدات للنطاق والدمج والتاريخ ومنع التصعيد، واختبارات PostgreSQL عبر HTTP للحساب والدخول والتصفية والتصدير والحفظ ومراجعة الطلب وسحب الصلاحية والحذف. العرض الفعلي على iPhone يحتاج مراجعة بعد النشر.
