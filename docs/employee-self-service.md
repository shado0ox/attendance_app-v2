# Employee portal tabs and private self-service

The employee portal now separates Schedule, Attendance and absence, Profile, Requests, and Settings. Settings contains password changes, biometric enrollment, automatic attendance preferences, email verification and the privacy link. Daily punch actions precede the employee's monthly history. Narrow screens can scroll the tab bar horizontally, and request dialogs scroll vertically.

Employees may edit their display name, phone, email and optional photo. Official HR name, username, department, status, permissions, schedule and credentials are not editable through this API. Company and employee IDs come from the validated employee session; supplied target IDs cannot redirect reads or writes. Email uniqueness is enforced transactionally across accounts, and changing an address revokes its previous email proof. Profile changes are audited without photo content or secrets; unchanged saves create no additional writes.

Photo uploads accept JPEG/PNG/WebP up to 8 MiB on the device, crop to a 384px square, re-encode as JPEG, and discard original metadata before upload. The server bounds encoded photos to 300 KiB, validates raster signatures, rejects SVG and remote URLs, and supports removal. Photos are stored separately under an opaque company/account key, not inside the bulk company data blob; the employee receives only their own photo. This prevents every admin schedule save from uploading all staff photos and reduces the risk of the previous payload-size failure. Company deletion removes these separate photo records too.

`GET/PATCH /api/employee-profile?companyId=...` are employee-only. `GET /api/employee-attendance?companyId=...&month=YYYY-MM` returns only that employee's rows and approved leave, analyzed against the published schedule using the existing first-in/last-out and Riyadh-time rules. Future or ongoing shifts are not absent; approved leave and rest are excluded. Missing/invalid/double-shift punches remain review items. The employee sees date, status, times, site names and recorded duration, with no raw GPS or other employee's records. These estimates do not approve payroll deductions.

Attendance history reads run when its tab opens, its month changes, punch state changes or the user requests refresh. There is no new hidden polling or automatic write cycle. Existing automatic attendance remains operational while switching tabs, with the existing foreground/PWA limits. An in-progress profile form is local and survives switching tabs while the page remains open; save to persist it. Only changed fields are sent, so a photo edit does not overwrite unrelated contact changes. iPhone/native device testing and individual account deletion remain separate App Store release requirements.

Validation: type checking, production/PWA build, unit tests and PostgreSQL integration cover self-only access, restricted fields, global email conflicts and verification invalidation, separate photo storage/removal, scoped monthly punches, absence/leave/rest, no-op saves and read-only reports.
