# تذكيرات واتساب لكل شركة

الميزة معطلة افتراضيًا ومستقلة عن إشعارات PWA. الإدارة صاحبة صلاحية `canManageSettings` لجميع أقسام الشركة تضبطها من الإعدادات. لا يملك مدير القسم أو الموظف الوصول إلى بيانات الربط. حساب المنصة لا يقرأ إعدادات الشركات الأخرى.

## التجهيز الآن ثم الربط لاحقًا

يمكن حفظ النطاق والمواعيد والأرقام بدون حساب Meta. التفعيل يتطلب حفظ Phone Number ID، Access Token، Meta App Secret، Webhook Verify Token ورابط بوابة HTTPS وأسماء القوالب المطلوبة. الرقم المرسل للعرض فقط؛ المعرف هو المستخدم في API. الإصدار الافتراضي v26.0 وقابل للتعديل عند ترقيته في Meta.

الأسرار مشفرة AES-256-GCM مع ربط التشفير بالشركة والحقل. لا تعود إلى واجهة المتصفح ولا تسجل في سجلات الإرسال. ترك خانة السر فارغة يحافظ على القيمة السابقة. استخدم `WHATSAPP_ENCRYPTION_KEY` ثابتًا قويًا على السيرفر، وانسخه احتياطيًا بأمان. بدون هذا المتغير يستخدم مفتاح JWT المستقر الموجود في النظام. عند تغيير مفتاح التشفير يجب إعادة إدخال الأسرار؛ لا تغيره بدون خطة. حماية الوصول إلى السيرفر ونسخ قاعدة البيانات تظل ضرورية. لا توضع بيانات واتساب داخل mainData أو تصدير بيانات الموظفين.

## إعداد Meta

1. إعداد WhatsApp Business Platform / Cloud API ورقم الشركة ووسيلة الدفع حسب متطلبات Meta.
2. إنشاء توكن إنتاج بصلاحيات الإرسال المناسبة؛ التوكن المؤقت للتجربة فقط.
3. اعتماد قالبين عربيين على Meta. كل قالب يحتوي **ثلاثة متغيرات نصية في الجسم بهذا الترتيب**: اسم الموظف، اسم الدوام، رابط البوابة. لا تضف متغيرات رأس أو زر URL ديناميكي إلى هذين القالبين؛ الإرسال الحالي يستخدم الجسم فقط.
4. قالب الحضور مثال: «مرحبًا {{1}}، لم تسجل حضورك لدوام {{2}}. افتح البوابة لتسجيل الحضور: {{3}}».
5. قالب الانصراف مثال: «مرحبًا {{1}}، انتهى دوام {{2}} ولم تسجل الانصراف. افتح البوابة: {{3}}».
6. إضافة رقم الموظف بمفتاح الدولة وتوثيق موافقته قبل الإرسال. تغيير الرقم يلغي الموافقة في الواجهة حتى إعادة تأكيدها. الإدارة مسؤولة عن تسجيل طلبات الانسحاب وإلغاء الموافقة.
7. حفظ رابط Webhook الظاهر في الإعدادات في Meta مع Verify Token نفسه، وتفعيل اشتراك `messages`. يجب أن يكون السيرفر متاحًا لـ Meta عبر HTTPS. طلبات POST تُتحقق بتوقيع HMAC-SHA256 للجسم الخام باستخدام App Secret. لا يجوز استخدام رقم إرسال واحد لشركتين داخل النظام.
8. اختبار اتصال الحساب يتحقق من الوصول إلى رقم الإرسال فقط. اختبار الإرسال يرسل رسالة فعلية للموظف المختار بموافقته حتى عندما يكون العامل الدوري معطلًا. نجاح طلب API يعني القبول فقط؛ حالات التسليم والقراءة تظهر من Webhook. قد لا تتوفر القراءة حسب إعدادات المستلم. اعتماد القالب والتصنيف والتسعير من Meta.

## المواعيد والسلوك

- عامل السيرفر يفحص كل دقيقة. يستخدم جدول الدوام المنشور وتوقيت السعودية والفترتين والدوام الليلي.
- الحضور يبدأ افتراضيًا بعد 10 دقائق، يتكرر كل 10 دقائق، ويتوقف فور وجود بصمة محفوظة أو بعد ساعة من **بداية** الفترة؛ فترة التأخير لا تمدد الساعة.
- الانصراف يبدأ عند نهاية الفترة لمن سجل حضورًا ولم يسجل انصرافًا فقط. يتوقف عند تسجيل الانصراف أو بعد ساعة من نهاية الفترة. لا يسجل حضورًا أو انصرافًا تلقائيًا.
- البدء قابل للتعديل 0–50 دقيقة، والفاصل 10–60 دقيقة. نطاق التجربة المحدد هو الافتراضي؛ تفعيل الجميع يشمل فقط من لديهم رقم وموافقة.
- لا إرسال للموظف المؤرشف، أيام OFF/A، الإجازة أو الغياب المعتمد أو الشركة غير النشطة.
- لكل شركة/موظف/يوم/فترة/نوع/فاصل مطالبة محفوظة قبل الاتصال الخارجي. النسخ المتوازية وإعادة التشغيل لا تعيد الفاصل نفسه. لا يتم تعويض الفواصل الماضية بعد توقف السيرفر.
- عند خطأ Meta تُسجل شفرة الخطأ فقط، وعند انتهاء مهلة أو انقطاع غير محسوم تُسجل نتيجة غير مؤكدة. لا يُعاد إرسال الفاصل نفسه؛ قد تستأنف التذكيرات في الفاصل التالي إذا بقيت مستحقة. في حالة الانهيار بعد حفظ المطالبة وقبل الاتصال قد تضيع رسالة واحدة؛ الأولوية لمنع التكرار والمدفوعات المزدوجة.
- آخر 100 محاولة متاحة في الإعدادات مع الاحتفاظ 30 يومًا. حالات Webhook تُطابق بالشركة ورقم المرسل ومعرف الرسالة ولا تتراجع مع إعادة إرسال أحداث أقدم.
- لإيقاف العامل لجميع الشركات استخدم `ATTENDANCE_WHATSAPP_ENABLED=false`؛ الاختبار اليدوي يظل متاحًا للمسؤول.

لا يؤكد اكتمال البيانات اعتماد القوالب أو الدفع أو التسليم. الرسائل قد تكون مدفوعة؛ اختبر موظفًا واحدًا قبل التعميم. لا تتجاوز الرسالة فحص الموقع أو Passkey داخل البوابة.

## التحقق

`npm run lint`، `npm run build`، `node --import tsx --test tests/*.test.ts`.
اختبار PostgreSQL `node --import tsx tests/whatsappReminders.integration.ts` مضاف إلى CI؛ يستخدم مزود إرسال وهميًا لا يرسل إلى أرقام حقيقية. اختبار المتصفح يشغّل مكون الإعدادات الفعلي مع API تجريبي.
