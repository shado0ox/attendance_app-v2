# وفر دوام — تطبيق iOS للماك والآيفون

مشروع Xcode مستقل داخل `ios/WafrDawam/WafrDawam.xcodeproj`، مكتوب بـSwift وUIKit وWKWebView، دون CocoaPods أو npm أو سيرفر محلي. يعرض النظام الحالي عبر `https://attendance.xshadox.com/` ويحافظ على نفس أصل الموقع ومسارات API. يحتاج الإنترنت والسيرفر الحالي؛ لا يخزن نسخة بيانات مستقلة ولا يغيّر نظام الويب أو أندرويد.

اسم التطبيق النهائي «وفر دوام»، ومعرفه `com.xshadox.wafrdawam` وإصداره `1.0.0` (بناء 1)، بدون تسمية تجريبية. ملفات البناء الحالية غير موقعة للتوزيع لأن عضوية Apple Developer لم تتفعّل بعد؛ يلزم استكمال التوقيع والقدرات واختبار الجهاز قبل إرسال المتجر. حساب Apple Developer وحده لا يضمن القبول؛ يراجع إعداد الخصوصية والخصائص والتجربة النهائية قبل الإرسال، بما فيها متطلبات الحد الأدنى من الوظائف 4.2.

## فتح المشروع على الماك

ثبت Xcode من Mac App Store، وافتحه مرة لقبول الترخيص وتنزيل منصة iOS. يفضل أحدث إصدار متاح من Xcode. الحد الأدنى المستهدف للأجهزة iOS 16.4.

لتنزيل الفرع قبل دمجه:

```bash
git clone --branch feature/ios-mac-preview https://github.com/shado0ox/attendance_app-v2.git wafr-dawam-ios
cd wafr-dawam-ios
open ios/WafrDawam/WafrDawam.xcodeproj
```

بعد دمج التحديث يمكنك استخدام main بدل الفرع. لا يلزم تشغيل Docker أو Node لهذه النسخة.

1. من أعلى Xcode اختر Scheme باسم **WafrDawam**.
2. اختر محاكي iPhone، مثل iPhone 16 أو أي محاكي iPhone متاح، بدل Any iOS Device.
3. اضغط زر التشغيل ▶ أو `⌘R`. المحاكي لا يحتاج اشتراك المطور المدفوع أو شهادة توزيع.
4. سجل الدخول بحساب تجريبي موجود بالنظام. البيانات والحركات تذهب للسيرفر الحقيقي، لذلك استخدم موظفًا وشركة للتجربة ولا تسجل بصمات تجريبية لموظف فعلي.

في المحاكي يمكن محاكاة الموقع من Xcode: Debug → Simulate Location. تجربة دقة GPS الحقيقية والأذونات تحتاج آيفون فعلي.

## نسخة المحاكي الجاهزة من GitHub

Actions → **iOS Mac build** → أحدث تشغيل ناجح على نفس الفرع → Artifacts → **WafrDawam-iOS-Mac**.

تحتوي الحزمة على:

- `WafrDawam-Xcode-Source.zip`: مشروع Xcode بمصادره والأيقونة.
- `WafrDawam-Simulator.zip`: تطبيق `.app` للمحاكي، لا يثبت على آيفون فعلي ولا يرفع إلى App Store.
- `README-ar.md`: هذه التعليمات.
- `WafrDawam-Simulator.png`: لقطة من تشغيل التطبيق إن نجح اختبار التشغيل.

يمكن فك ملف المحاكي ثم سحب `WafrDawam.app` إلى محاكي iPhone مفتوح. لو بنية معالج الماك غير متوافقة، افتح المشروع وابنه محليًا بدل ملف المحاكي.

## تجربة آيفون فعلي قبل موافقة العضوية

1. وصل الآيفون بالماك ووافق على Trust، وفعل Developer Mode إن طلب iOS.
2. Xcode → Settings → Accounts: أضف Apple Account الخاص بك.
3. Target WafrDawam → Signing & Capabilities: اختر **Personal Team**، واترك Automatically manage signing مفعّلًا.
4. إذا كان Bundle Identifier مستخدمًا، غيّر `com.xshadox.wafrdawam` إلى معرف تجريبي فريد خاص بك.
5. اختر الآيفون واضغط Run. قد يطلب الجهاز الوثوق بالمطور من الإعدادات. توقيع Personal Team مؤقت وقد يحتاج إعادة التشغيل من Xcode بعد انتهائه، ولا يدعم كل قدرات الحساب المدفوع.

## الخصائص والتجهيزات المتبقية

- جلسة WKWebView دائمة ضمن التطبيق، لكنها منفصلة عن Safari. فتح Safari قد يتطلب تسجيل الدخول مرة أخرى.
- أذونات الموقع أثناء الاستخدام مضافة؛ لا توجد صلاحية موقع في الخلفية أو وعد ببصمة أثناء إغلاق التطبيق. اختبر الإذن ودقة GPS على جهاز فعلي.
- الوصول للموقع عبر HTTPS فقط. الصفحات داخل التطبيق محصورة بدومين النظام؛ الروابط الخارجية المسموحة تفتح خارج التطبيق عند الضغط عليها. لا يوجد تجاوز لشهادات TLS أو وصول للملفات المحلية.
- نوافذ المستندات تدعم إغلاقًا واضحًا. من زر ⋯ يمكن الرجوع وتحديث/طباعة الصفحة ومشاركة PDF. عند فتح معاينة طباعة من الموقع استخدم أمر «طباعة الصفحة» الأصلي من القائمة إذا لم يفتح مربع الطباعة تلقائيًا.
- Passkey داخل التطبيق يحتاج ربط Associated Domains بالتطبيق والدومين بعد توفر Team ID والقدرات المناسبة. لا تعتبر مفتاح مرور Safari مثبتًا داخل التطبيق قبل الربط والاختبار. لحساب يتطلب Passkey استخدم **⋯ → فتح في Safari** مؤقتًا؛ لا يتم تعطيل اشتراط Passkey أو تجاوزه.
- إشعارات PWA الحالية ليست إشعارات تطبيق iOS أصلي. خدمة APNs لم تربط في هذه النسخة ولا يمكن وعد وصول إشعار في الخلفية. تكتمل لاحقًا بعد تفعيل الحساب والتوقيع وإعداد السيرفر.
- لا يتم تعديل الموقع أو منع دخول الإدارة في هذا التحديث؛ النسخة تعرض بوابة النظام الحالية وصلاحيات الحساب نفسه.
- ملف `PrivacyInfo.xcprivacy` يصرح ببيانات وظائف النظام الأساسية، لكنه لا يغني عن مراجعة App Privacy في App Store Connect وفق الاستخدام الفعلي قبل النشر.

## بعد تفعيل الحساب

1. سجل التطبيق في App Store Connect بالمعرف `com.xshadox.wafrdawam` واختر Team الشركة في Xcode. لو كان المعرف محجوزًا لفريق آخر، عدله في Xcode وفي ملفات ربط الدومين.
2. أضف Associated Domains في Signing & Capabilities مع `webcredentials:attendance.xshadox.com`.
3. ملفات `ios/Signing/*.example` قوالب فقط؛ لا يفعّلها بناء المحاكي. استبدل `YOUR_TEAM_ID` بمعرف فريقك ومعرف التطبيق النهائي، وانشر ملف `apple-app-site-association` الفعلي على `https://attendance.xshadox.com/.well-known/apple-app-site-association` بصيغة JSON، دون امتداد أو إعادة توجيه. يلزم ضبط تقديمه من السيرفر/الوكيل والتحقق منه قبل تجربة Passkey.
4. اختبر Passkey والموقع والطباعة والمشاركة على آيفون فعلي. جهز APNs وربط إشعارات التطبيق عند طلب تفعيله.
5. راجع واجهة التطبيق وخصوصيته وحساب المراجع ومتطلبات المتجر، وثبت الاسم «وفر دوام» والإصدار النهائي قبل الرفع.
6. من Xcode اختر جهاز iOS عام ثم Product → Archive → Distribute App → App Store Connect. ارفع إلى TestFlight واختبر قبل الإرسال للمراجعة.

لا ترفع شهادات `.p12` أو ملفات provisioning أو كلمات مرور أو مفاتيح APNs إلى Git. لا يحتاج بناء المحاكي أي منها.

## تحقق البناء

يشغّل Workflow `iOS Mac build` فحص ملفات plist، واختبارات سياسة الروابط، وبناء المحاكي، وبناء جهاز iOS بدون توقيع. كما يشغّل تطبيق المحاكي ويلتقط صورة؛ لا يسجل دخولًا أو بصمة تلقائية ولا يثبت نجاح الموقع/Passkey/الإشعارات على جهاز فعلي.
