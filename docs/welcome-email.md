# رسائل الترحيب للموظفين

أنشئ مفتاح Resend مستقلًا لبرنامج الحضور بصلاحية Sending access، وقيّده بالدومين الموثق إن أمكن. يمكنك استخدام حساب Resend الموجود؛ حدود الإرسال مشتركة مع برنامج الرواتب. لا تضع المفتاح في الواجهة أو Git أو المحادثة.

اضبط ملف `.env` على السيرفر:

```dotenv
RESEND_API_KEY=re_replace_locally
RESEND_FROM="الحضور <attendance@your-verified-domain.com>"
APP_URL=https://your-attendance-domain.com
```

ثم أعد إنشاء الحاوية لقراءة البيئة:

```bash
docker compose up -d --build --force-recreate attendance_app
```

أضف بريد الموظف، واترك خيار إرسال الترحيب مفعّلًا. بعد تأكيد حفظ الموظف تطلب الواجهة الإرسال من السيرفر. الرسالة تشمل رابط البرنامج، واسم المستخدم، وشرح جدول الدوام والبصمة وطلبات تعديل الدوام، وتعليمات Safari وChrome. لا ترسل كلمات المرور.

عند فشل البريد يبقى الموظف محفوظًا. زر «رسالة الترحيب / إعادة المحاولة» يتيح المحاولة من بطاقة الموظف، بما فيها الموظفون الحاليون. الإرسال إلى البريد المحفوظ فقط، للمسؤولين داخل شركتهم. نتيجة القبول من Resend لا تثبت التسليم؛ راجع حالة التسليم أو الارتداد بلوحة Resend.

يُحفظ سجل مستقل في system_data، مع قفل لمنع الإرسال المتزامن ومفتاح منع تكرار ثابت ونسخة ثابتة من محتوى الرسالة. تعديل الموظف أو تحديث الصفحة لا يعيد الإرسال. لا توجد مهام دورية أو قراءة/كتابة مستمرة. إذا أُغلقت الصفحة بعد الحفظ وقبل طلب الإرسال، استخدم الزر من بطاقة الموظف. لا تعيد المحاولة بعد مرور 23 ساعة على طلب سابق غير مؤكد: تحقق من Resend أولًا لتجنب إرسال مكرر خارج نافذة منع التكرار. عند تغيير البريد بعد بدء الإرسال، تظل المحاولة مرتبطة بالعنوان الأصلي؛ السجل يحمي من إرسال رسالة أخرى دون مراجعة.

اختبار النشر: أضف موظفًا تجريبيًا ببريد تملكه، تأكد من وصول الرسالة وصحة الرابط على الهاتف، واضغط زر الترحيب مجددًا للتأكد من ظهور «سبق قبول الرسالة». فشل إعداد Resend يجب ألا يمنع حفظ الموظف.
