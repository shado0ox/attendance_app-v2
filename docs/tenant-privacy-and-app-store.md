# عزل الشركات والاستعداد لـ App Store

## الصلاحيات بعد هذا التحديث

| الحساب | بيانات العمل | الشركات المشتركة |
|---|---|---|
| مسؤول المنصة superadmin | الشركة الافتراضية 101 فقط | الاسم، الرمز، حالة الاشتراك، تاريخ الانتهاء، قيمة الاشتراك وتاريخ الإنشاء؛ التفعيل والإيقاف والتجديد والحذف |
| صاحب الشركة | شركته فقط | لا يمكنه الوصول لشركة أخرى |
| مسؤول الشركة المفوض | شركته وأقسامه وصلاحياته المخزنة | لا إدارة اشتراكات |
| الموظف | بيانات حسابه والجدول المسموح داخل شركته | لا إدارة شركات |

فحص النطاق في API يشمل التقارير والتصدير والملفات الموحدة والإشعارات والبريد والجداول والأرقام المباشرة للسجلات، ويعامل حتى جلسة superadmin قديمة تحمل معرّف شركة أخرى كنطاق 101. تعديل بيانات دخول مدير شركة أخرى عبر اشتراكات المنصة ممنوع. قائمة الشركات لا تعرض بيانات الدخول أو البريد أو الشعار الخاص بالشركات المشتركة.

صاحب الشركة الجديدة يستخدم «تسجيل شركة بواسطة صاحبها» من شاشة الدخول دون جلسة إدارية، ويختار اسم المستخدم والبريد وكلمة المرور ويطلع على السياسة. تخصيص الرمز تلقائيًا من 102. التسجيل يظل pending حتى تفعيل مسؤول المنصة، ولا يسمح الدخول أثناء التعليق/الانتهاء؛ التحقق يشمل الجلسات الموجودة. التسجيل محدود بعشر محاولات في الساعة لكل عنوان اتصال بالعملية الحالية؛ عند التوسع استخدم حدًا مشتركًا في الوكيل أو Redis مع ضبط trusted proxies، وتحقق البريد ومكافحة الإساءة. لا تفعّل ثقة الوكلاء بلا تحديد الوكيل الموثوق.

**الحسابات القديمة:** إذا كانت كلمة المرور معروفة سابقًا لمسؤول المنصة، يجب أن يغيرها صاحب الشركة بنفسه في الإعدادات > حماية حساب صاحب الشركة. لا يستطيع هذا الإصدار محو معرفة كلمة مرور سبق مشاركتها. تدوير كلمة المرور يلغي كل جلسات صاحب الشركة القديمة، والجديدة تتطلب الدخول بكلمة المرور الجديدة. لا تشارك كلمة المرور الجديدة مع مسؤول المنصة.

تخزين جداول المسؤولين محليًا أُلغي، وتُحذف نسخ الجداول المحلية السابقة عند دخول المسؤول أو تبديل الحساب أو الخروج. يظل تخزين الموظف المحدود متاحًا دون اتصال. API لا تُخزّن عبر service worker.

حذف الشركة عملية ذرية تحذف بياناتها الحية من companies وmainData وadmins وattendance وrequests وregistrationRequests وauditLog وattendanceMonths وحالات الترحيب والتحقق بالبريد وصلاحيات المسؤولين وقراءة التنبيهات والموافقة على السياسة ومراجعة كلمة المرور. يُحجز معرّف الشركة المحذوفة لمنع إعادة استخدامه ووصول JWT قديم إلى بيانات شركة جديدة. النسخ الاحتياطية السابقة لا تُمحى بهذا الإجراء؛ تطبيق مدة الاحتفاظ مسؤولية التشغيل. لا يُجرى حذف تلقائي لمجرد انتهاء الاشتراك.

## حدود الحماية والتشغيل

هذه صلاحيات التطبيق، وليست تشفيرًا ضد مالك الخادم أو PostgreSQL. النسخ الاحتياطية التشغيلية تشمل مخطط التطبيق كله، ولا يوجد رابط لتنزيل محتواها في API. افصل وصول تشغيل البنية التحتية عن مسؤول اشتراكات المنصة؛ أقل صلاحيات، حسابات شخصية، تسجيل وصول تشغيلي، HTTPS وقرص/نسخ احتياطية مشفرة، إدارة أسرار، مدة احتفاظ معلنة، وخطة استعادة تتعامل مع طلبات الحذف السابقة ولا تعيد حسابًا محذوفًا للخدمة. يلزم تصميم مفاتيح تحت تحكم الشركات إذا كان المطلوب منع حتى مالك الخادم من قراءة المحتوى.

لا تُرسل مفاتيح Resend أو JWT أو كلمات المرور أو النسخ الاحتياطية للمستخدم أو ضمن ملفات التطبيق. يتولى العميل تخزين JWT في localStorage حاليًا؛ قبل النسخة الأصلية قرر التخزين الآمن Keychain وحدود WebView وCSP والحماية من XSS، وحماية حساب المنصة بـ MFA، وسياسة انتهاء/إلغاء كل أنواع الجلسات. عزل التطبيق الحالي لا يغني عن مراجعة أمنية مستقلة أو RLS بمستخدم قاعدة بيانات محدود عند تحويله لخدمة عامة.

## إعداد صفحة السياسة

الصفحة العامة `/privacy.html` متاحة دون الدخول ومرتبطة بشاشة الدخول وباقي شاشات التطبيق. أضف هذه القيم في `.env` الخاص بالخادم، ولا تستخدم بيانات وهمية:

```dotenv
PRIVACY_CONTROLLER_NAME="الاسم القانوني لجهة تشغيل الخدمة"
PRIVACY_CONTACT_EMAIL="بريد الدعم والخصوصية الفعلي"
PRIVACY_RETENTION_NOTICE="مدة الاحتفاظ الفعلية بسجلات العمل والنسخ الاحتياطية، أساس الاستثناءات، وكيفية طلب الحذف ومدة تنفيذه"
```

أعد بناء الحاوية بعد تعديل البيئة. تعرض الصفحة حالة عدم اكتمال إذا غابت البيانات، ولا تدّعي وجود حذف حساب فردي لم يُنفذ. راجع اتفاق معالجة البيانات بين المنصة والشركة، التزامات المنطقة الفعلية ومقدمي الاستضافة والبريد، وموافقة الموظفين المناسبة قبل الإطلاق.

## متطلبات Apple المتبقية — الإصدار الحالي ليس جاهزًا للإرسال للمتجر

1. **5.1.1(v): حذف الحساب الفردي من داخل التطبيق.** يجب توفير إجراء واضح لإنشاء طلب حذف وتنفيذه فعليًا، بعد التحقق من هوية المستخدم، وإلغاء الجلسات والاعتمادات وحذف البيانات غير المطلوب الاحتفاظ بها قانونًا. إيقاف الموظف أو حذف الشركة بواسطة المنصة لا يحقق هذا الشرط. لا تجعل المسار مجرد «تواصل مع الدعم». حدد قانونيًا سجلات العمل الواجب الاحتفاظ بها، اعرضها ومدة تنفيذ الحذف، ودعم حسابات الموظف والمدير وصاحب الشركة ونقل ملكية الشركة حيث يلزم.
2. **5.1.1(i–iv) و5.1.5:** استكمال السياسة وجهة التشغيل والاحتفاظ، موافقة قابلة للسحب، توضيح الإذن قبل طلب الموقع وبيان الغرض في NSLocationWhenInUseUsageDescription، بديل طلب تصحيح حضور عند رفض الموقع. لا تطلب Background Location إلا إذا بُنيت وظيفة أصلية ضرورية ومعلنة واختُبرت؛ PWA لا يضمن البصمة في خلفية iPhone. أزل إجبار البريد للتصفح إذا لم يكن ضروريًا للوظيفة الأساسية، واحتفظ بالتحقق اختياريًا حيث يمكن.
3. **App Privacy:** الإفصاح عن الاسم والبريد والجوال ومعرّفات المستخدم والموقع الدقيق ومحتوى طلبات الموظف وبيانات الاستخدام/التشخيص إن جُمعت فعليًا، وربطها بالمستخدم وأغراضها ومقدمي الخدمة. بيانات WebView محسوبة أيضًا. بصمة الوجه/الإصبع المحلية ليست صورة بيومترية مخزنة بالسيرفر؛ لا تخلطها مع الموقع ومعرّفات الاعتماد المرسلة. راجع SDKs والـ privacy manifests وRequired Reason APIs بعد اختيار تقنية iOS؛ لا تحدد إفصاحات غير موجودة فعليًا.
4. **4.2:** بناء تجربة iOS مناسبة ذات منفعة فعلية، وليس مجرد غلاف موقع. اختبار TestFlight على أجهزة iPhone، الدخول WebAuthn والجلسات، RTL، Accessibility وDynamic Type، التصدير والمشاركة، رفض الأذونات، انقطاع الاتصال والتحديثات وحالات الخطأ. PWA الحالي ليس تطبيق App Store؛ لم يُبنَ مشروع Xcode أو يُختبر جهاز iPhone بهذا التحديث.
5. **3.1:** تحديد نموذج بيع الشركات. قد ينطبق 3.1.3(c) إذا البيع حصريًا للمنظمات لموظفيها؛ ليس إعفاءً تلقائيًا للبيع للأفراد. لا توجد عملية دفع جديدة بهذا التحديث. راجع عرض إدارة الاشتراكات والتفعيل داخل نسخة iOS، ولا تضف شراء خارجيًا أو دعوات دفع مخالفة للسوق المستهدف. رسوم الشركات الجديدة حاليًا 0 لأن صاحب الشركة لا يحدد سعرًا؛ السعر التجاري يُحدد خارج بيانات التسجيل وبإجراء تسعير مستقل لاحقًا.
6. **2.1 وما قبل الإرسال:** حساب مراجعة ببيانات تجريبية لشركة مستقلة، سيرفر HTTPS عامل، طريقة مراجعة الحضور بعيدًا عن المقر ببيانات تجريبية لا تُزيّف حضور العملاء، ملاحظات الوظائف والموقع والاشتراكات، Support URL وPrivacy Policy URL، صور حقيقية، معلومات اتصال وتقييم عمر صحيح. لا تعط Apple أو غيرها حساب المنصة أو حساب عميل حقيقي.

لا توجد آلية تضمن كل احتمالات القبول؛ راجع القواعد عند إرسال النسخة الأصلية، فهي تتغير، والقرار النهائي لـ App Review.

## التحقق

`npm run lint`، `npm run build`، `node --import tsx --test tests/*.test.ts`، ثم تكامل PostgreSQL كما في workflow. اختبار tenantPrivacy.integration يختبر منع نطاق الشركات لكل من جلسة المنصة الحديثة والقديمة، منع إعادة تعيين بيانات المدير، السجلات بالأرقام دون companyId، التعليق مع JWT موجود، تدوير كلمة المرور وإلغاء الجلسات، الحذف وحجز المعرّف. الاختبارات لا تُرسل بريدًا حقيقيًا ولا تحذف بيانات تشغيلية؛ تعمل في قاعدة CI فقط.
