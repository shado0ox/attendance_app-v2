# حالات الموظفين وسجل التعديلات

الموظف الحالي بدون status يُعامل كنشط، بدون تحويل أو كتابة جماعية. حالات الموظف: active (نشط)، suspended (موقوف)، archived (مؤرشف).

شؤون الموظفين تعرض النشطين افتراضيًا، مع فلتر لكل حالة أو كل الحالات. بديل الحذف هو الأرشفة، مع سبب وتأكيد. التفعيل/الاستعادة يحتفظ بنفس الهوية والبصمات وبيانات الحساب. لا يسمح مسار الحفظ بحذف موظف موجود نهائيًا.

الإيقاف والأرشفة يمنعان الدخول بكلمة المرور وطلب WebAuthn واستخدام التوكنات السابقة لقراءة الجدول أو تسجيل بصمة أو تعديل البريد أو تقديم طلب. كل طلب محمي للموظف يقرأ حالته فقط من قاعدة البيانات، بدون مهام دورية أو تحميل كامل بيانات الشركة. الطلب الجاري بالفعل قبل تغيير الحالة قد يكتمل؛ الإجراء يؤثر على الطلبات التالية. إدارة التقارير التاريخية تظل متاحة للمسؤولين.

اقتراح توزيع الدوام وتنبيهات التغطية يستخدمان الموظفين النشطين فقط. جدول الإدارة يحتفظ بموظفي القسم وسجلاتهم ويعرض الحالة على اسم الموظف. الجداول القديمة لا تُمسح آليًا عند الإيقاف أو الأرشفة؛ راجع توزيع الفترات المستقبلية بعد تغيير الحالة.

إضافة الموظف وتعديل الحقول ونقل القسم وتغيير الحالة وتسجيل البريد وتغيير رمز الدخول تُسجل في audit_log داخل نفس معاملة حفظ البيانات. نجاح الحفظ يرسل بعد نجاح المعاملة. السجل يعرض آخر 100 تعديل للموظف، حسب الشركة، مع الاسم والتوقيت بتوقيت الرياض والقيم قبل/بعد. كلمات المرور ومفاتيح البصمة ليست جزءًا من تفاصيل السجل؛ تغيير الرمز يسجل كإجراء محجوب. لا يوجد تعديل أو حذف للسجل عبر API. السجل يبدأ من هذا الإصدار ولا يعيد إنشاء تاريخ لم يكن مسجلًا.

حفظ مفاتيح WebAuthn أصبح تحديثًا محدودًا لمفاتيح الموظف داخل معاملة بدل استبدال كل بيانات الشركة من نسخة قديمة، لحماية الحالة والبريد والجداول من الكتابة فوقها.
