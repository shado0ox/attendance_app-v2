# صحة النظام والنسخ الاحتياطية

تظهر صفحة «صحة النظام» لمسؤول الشركة ذي صلاحية الإعدادات العامة، ولا تظهر لمدير قسم محدود. تنفذ الفحص عند فتحها أو الضغط على تحديث الحالة، دون طلبات دورية أو كتابة بيانات الموظفين. تعرض اتصال PostgreSQL والجداول الأساسية، النسخ، آخر حالة لكل موظف ونوع رسالة، إصدار البناء، وآخر 20 خطأ API للشركة من سجل محدود إلى 100 خطأ. لا يعرض السجل محتوى الطلبات أو كلمات المرور أو رموز التأكيد.

## تشغيل Docker

```bash
cd /mnt/ssd/projects/attendance_app-v2
git pull origin main
docker compose up -d --build attendance_app
docker compose ps
```

يشمل Docker أدوات PostgreSQL. يرتبط مجلد `./backups` بالمجلد `/app/backups` داخل الحاوية؛ يبقى محفوظًا عند إعادة البناء. لا يُضاف إلى Git أو صورة Docker. لا تحذف هذا المجلد عند تنظيف المشروع.

يُفعَّل النسخ تلقائيًا في Compose ما لم يكن `BACKUP_ENABLED=false`. يبدأ فحص الموعد بعد دقيقة من تشغيل السيرفر، ثم ينشئ نسخة إذا مر يوم على آخر نجاح. لا يعيد النسخ عند كل فتح أو تحديث للواجهة؛ يعيد المحاولة بعد ساعة عند الفشل. يحتفظ بآخر 14 ملف نسخة، وقد تشمل نسخًا يدوية من اليوم نفسه. التشغيل خارج Docker يحتاج `BACKUP_ENABLED=true` وأدوات `pg_dump` و`pg_restore`. `BACKUP_DIR` يحدد المجلد، والاتصال يستخدم إعدادات التطبيق الحالية.

النسخة أرشيف PostgreSQL مخصص لمخطط `DB_SCHEMA` (الافتراضي `shift_app`) ويشمل كل شركات ذلك المخطط، لا قواعد الرواتب أو مخططات أخرى. تحتوي بيانات حساسة، بما فيها حالات البريد وبيانات الحسابات؛ احمِ مجلدها وصلاحياته. يسمح للسوبر أدمن وحده بإنشاء النسخة يدويًا واختبار الاسترجاع. يمكن لمسؤول الشركة عرض بيانات صحة النسخ دون تنزيل محتواها.

## التحقق والاسترجاع

بعد النشر، سجّل الدخول بالسوبر أدمن وافتح «صحة النظام»، واضغط «إنشاء نسخة الآن» ثم «اختبار الاسترجاع». فحص بنية الأرشيف عند الإنشاء لا يثبت نجاح استرجاع البيانات. اختبار الاسترجاع يتحقق من بصمة SHA-256، وينشئ قاعدة باسم عشوائي يبدأ بـ `attendance_restore_check_`، ويسترجع إليها، ويفحص الجداول وقراءة البيانات ثم يحذفها. لا يقبل اسم قاعدة مستهدفة من المستخدم، ولا يسترجع إلى قاعدة التطبيق الحية.

يتطلب الاختبار صلاحية `CREATEDB` لمستخدم PostgreSQL؛ نقصها يفشل الاختبار دون تعطيل النسخ العادي. إذا تعذر حذف قاعدة الاختبار، تظهر رسالة تتضمن اسمها لمراجعة مسؤول PostgreSQL. يجب فحص هذه الرسالة وإزالة القاعدة المؤقتة بعد مراجعتها.

النسخ محلية فقط: تلف القرص أو فقد السيرفر قد يفقد الأصل والنسخ معًا. انسخ الأرشيف وملف `backup-status.json` دوريًا إلى تخزين مستقل وآمن. هذه المرحلة لا تضيف رفعًا سحابيًا تلقائيًا. الاسترجاع الفعلي بعد حادث يجب أن يراجعه مسؤول قاعدة البيانات في نافذة صيانة وبعد أخذ نسخة من الحالة الحالية؛ زر الفحص ليس زر استرجاع الإنتاج.

## البريد وإصدار التطبيق

«مقبولة لدى Resend» تعني قبول المزود للطلب ولا تؤكد التسليم أو تمنع الارتداد. تُراجع تفاصيل التسليم من Resend. تظهر آخر حالة لكل موظف ونوع رسالة، وليست سجل جميع الرسائل التاريخية. إعادة محاولة الترحيب تستخدم هوية الإرسال نفسها خلال 23 ساعة، ولا تُعاد رسالة مقبولة. تغيير البريد أو انتهاء هذه النافذة يحتاج مراجعة سجل المزود أولًا لتجنب التكرار. رموز التأكيد يطلبها الموظف من حسابه؛ لا تكشفها الصفحة ولا تعيد الإدارة إرسال رمز قديم.

معرّف البناء يُشتق من واجهة الإنتاج والسيرفر. تقارن الصفحة ملف الواجهة المفتوح بملفات الإصدار الحالي وتنبه إذا كانت نسخة PWA قديمة؛ يستخدم الموظف آلية تحديث التطبيق القائمة. لا تجبر الصفحة التطبيق على إعادة التحميل ولا تضيف فحصًا دوريًا لقاعدة البيانات. فحص Docker كل دقيقة يختبر حياة عملية HTTP فقط دون اتصال بقاعدة البيانات.

## التحقق الآلي

تشمل الاختبارات الصلاحيات وعزل الشركات، تنقيح بيانات البريد، إعادة محاولة الترحيب دون تكرار، قفل عمليات النسخ، حفظ آخر نجاح عند الفشل، كشف فقد الملف وتقادم النسخة، وتحديد حجم سجل الأخطاء. اختبار PostgreSQL ينشئ أرشيفًا حقيقيًا، يسترجعه في قاعدة مؤقتة ويحذفها، ويرفض أرشيفًا تالفًا دون تعديل بيانات الإنتاج التجريبية. لا تحل الاختبارات محل تجربة النشر على OrangePi أو تجربة PWA على آيفون.
