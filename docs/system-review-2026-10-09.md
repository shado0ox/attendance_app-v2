## السلوك بعد الإصلاح

الموظف يوقّع ويؤكد اعتماد الطلب، ثم يحصل على رابط المشاركة مباشرة دون موافقة الإدارة. لا يمكن لجلسة الموظف عرض النموذج أو طباعته أو تعديله أو إلغاؤه أو حذفه. المدير يدخل بحساب إدارة الشركة أو مدير قسم يمتلك `canApproveRequests`، ثم يراجع ويوقّع؛ لا يتم استبدال جلسة بوابة الموظف عند الدخول من صفحة الرابط. الإدارة تتابع الطلب وتطبعه وتحذفه حتى بعد اعتماده، وعند الحذف تختفي علاماته ويُبطل الرابط.

العلامة «استئذان معتمد» تظهر داخل اليوم في بوابة الموظف والجدول وكشف الحضور والطباعة وCSV. العلامة ليست إشعار دفع للهاتف، ولا تغيّر الساعات أو الغياب أو الخصومات تلقائيًا.

التحقق من المدير يعتمد على حسابه وصلاحياته؛ لا يستطيع النظام استنتاج أن حسابين مستقلين بهويات مختلفة يخصان الشخص نفسه. يجب عدم مشاركة حسابات المديرين.

- النسخة الأصلية: نجاح TypeScript و97 اختبار وحدة.
- الفرع المعدل محليًا: نجاح TypeScript والبناء و105 اختبارات وحدة.
- الاختبارات المضافة تشمل حساب الموظف، المدير بلا صلاحية، الشركة والقسم الآخر، اسم المدير المزور، الاعتماد المتزامن، الحذف، الأيام بلا بصمة، نطاق الموظف، بيانات الطلب المزورة، حالات الموظفين وتداخل الفترات.
- اختبارات الواجهة تشمل المشاركة والطباعة وPDF والرجوع، تحديث التفاصيل المفتوحة، ودخول المدير.
- اختبارات PostgreSQL والمتصفح تُنفّذ في سير عمل `Attendance checks` على طلب الدمج. تعذر تجهيز PostgreSQL وتنزيل Chromium في بيئة المراجعة المحلية.
- بعد تحديث الاعتماديات بقيت أربع نتائج متوسطة في سلسلة `drizzle-kit → @esbuild-kit → esbuild`. العلاج المقترح من npm يتطلب تغييرًا غير متوافق؛ لم يُطبّق. هذا المسار خاص بأداة تطوير قاعدة البيانات، وليس مسار معالجة طلبات Express؛ صورة Docker الحالية تنسخ اعتماديات التطوير أيضًا.
